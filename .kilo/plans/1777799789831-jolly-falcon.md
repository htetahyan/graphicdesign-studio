# Drizzle ORM Migration Plan

## Why Drizzle ORM?

| Feature | Current (Supabase JS) | After (Drizzle ORM) |
|---------|----------------------|---------------------|
| Type Safety | Manual `as any` casts everywhere | Full inferred types from schema |
| Migrations | Manual `.sql` files run in Supabase editor | `drizzle-kit generate` + `drizzle-kit migrate` |
| Prepared Statements | ❌ Not available | ✅ `db.query.*.prepare()` |
| Schema as Code | Raw SQL + Supabase dashboard | TypeScript schema, version-controlled |
| Query Performance | REST API overhead (PostgREST) | Direct PostgreSQL wire protocol |
| Join Queries | Limited to Supabase's embed syntax | Full SQL joins, subqueries, CTEs |
| Transactions | Not supported via JS client | ✅ `db.transaction()` |

## Architecture Decision

- **Driver**: `postgres.js` (recommended by Drizzle for Supabase)
- **Connection**: Supabase Connection Pooler (Transaction mode) with `prepare: false`
- **Keep Supabase JS for**: Storage operations only (`upload`, `getPublicUrl`)
- **Schema**: `drizzle-kit pull` to introspect existing DB, then maintain in code

## Implementation Steps

### Phase 1: Setup (New files, no breaking changes)
- Install packages: `drizzle-orm`, `postgres`, `drizzle-kit`
- Add `DATABASE_URL` to `.env`
- Create `drizzle.config.ts`
- Run `drizzle-kit pull` to introspect existing schema
- Refine generated schema with proper types and relations
- Create `lib/db/index.ts` with connection

### Phase 2: Schema & Prepared Statements
- Define all tables in `lib/db/schema.ts`
- Define relations in `lib/db/relations.ts`
- Create prepared statements for frequent queries in `lib/db/prepared.ts`

### Phase 3: Convert Server Actions (one-by-one)
- Convert `user-auth.ts` first (login, signup, session)
- Convert `brand.ts` (CRUD)
- Convert `generate.ts` + `process-job/route.ts`
- Convert `admin.ts`, `recharge.ts`, `admin-payments.ts`
- Convert `inspirations.ts`, `admin-inspirations.ts`

### Phase 4: Cleanup
- Remove `lib/database-queries.ts` (replaced by Drizzle relational queries)
- Remove `lib/database-optimization.ts` (views no longer needed)
- Remove old `.sql` migration files
- Update `lib/supabase.ts` to only export storage client
- Add npm scripts: `db:generate`, `db:migrate`, `db:push`, `db:studio`

## Additional Notes from Codebase Analysis
- Existing Drizzle schema (`lib/db/schema.ts`) lacks some indexes (e.g., `idx_generation_jobs_status`, `idx_brands_user_id`), unique constraints (e.g., on `users(signup_ip)`), and views.
- Row-level security (RLS) policies and storage policies must be handled separately, as Drizzle doesn't manage them.
- Ensure indexes and policies are applied post-migration via Supabase SQL editor or scripts.

**IMPORTANT**: This is a large migration. I recommend doing it in phases.
