# Plan: Fix Automatic Brand Selection Changes in Generate Page

## Problem Analysis
The brand selector in the generate page keeps changing automatically without user input. Analysis reveals the issue is in the `useBrandSync` hook's logic:

- The first `useEffect` always attempts to set `selectedBrandId` to a "preferred" brand (from URL query param `?brand=` or localStorage `lastBrandId`) whenever the `brands` prop changes, even if the current selection is valid.
- This causes the selection to reset unexpectedly when:
  - The `brands` array prop updates (e.g., due to re-renders or prop changes).
  - The preferred brand (from URL/localStorage) differs from the current manual selection.
  - Page loads with an old URL brand param while user had selected something else.

## Root Cause
In `useBrandSync`, the initialization effect overrides valid existing selections with the "preferred" brand on every `brands` change, leading to unwanted resets.

## Solution
Modify `useBrandSync` to preserve valid existing selections and only reset when necessary:

1. Only set a new `selectedBrandId` if the current one is empty or invalid.
2. If invalid or empty, prioritize URL param, then localStorage, then first brand.
3. Ensure the second effect still syncs URL and localStorage when selection changes manually.

## Implementation Steps
1. Update `useBrandSync` hook to check if `selectedBrandId` is valid before resetting.
2. Test the fix by simulating brand changes and selections.
3. Verify no unintended side effects in multi-tab scenarios or after brand CRUD operations.

## Testing
- Load generate page with URL `?brand=invalid` → should default to valid brand without looping.
- Select a brand manually → should update URL and persist.
- Change brands externally (simulate prop update) → should not reset valid selection.
- Open multiple tabs → selections should sync appropriately without conflicts.

## Expected Outcome
Brand selection remains stable and only changes when explicitly invalid or on initial load with preferences.
