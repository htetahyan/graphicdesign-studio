# Fix Image Preview Delay (90s vs 47s Generation)

## Problem
Image previews take ~90 seconds to appear, while actual generation completes in ~47 seconds. The extra ~43 seconds is caused by conservative polling backoff (5s start, 30s max), delaying completion detection by 10-30s.

## Root Cause Analysis
- Polling uses exponential backoff: intervals 5s → 7.5s → 11.25s → ... → 30s
- If generation completes between polls, detection is delayed
- No adaptive polling; remains slow even when progress is high (90% in 30s)
- Progress simulation reaches 90% in 30s, but actual polling continues conservatively

## Solution Overview
Implement adaptive polling that accelerates as generation progresses, reducing average detection delay from 15-25s to 2-5s.

## Implementation Steps

### 1. Modify Polling Logic in `use-generate-form.ts`
- Track time elapsed since job start
- Switch to aggressive polling (1-2s intervals) after 40s elapsed (near generation completion)
- Maintain current backoff early to avoid overloading API

### 2. Update Progress Hook (`use-generate-progress.ts`)
- Ensure progress accurately reflects actual generation timing (47s total)
- Adjust progress curve to match real completion windows

### 3. Test Changes
- Monitor polling intervals and detection times
- Verify no increased API load or rate limits
- Confirm preview appears within 50-55s total

## Expected Outcomes
- Reduce preview delay by 20-30s
- Total user wait: 50-55s instead of 90s
- No impact on generation performance

## Files to Modify
- `app/(authenticated)/generate/use-generate-form.ts` (polling logic)
- `app/(authenticated)/generate/hooks/use-generate-progress.ts` (progress timing)

## Risk Assessment
- Low: Adaptive polling only increases frequency near completion when generation is likely done
